# AUC、ROC、PR 与早停监控指标选择

> 在给 WideNDeep 模型引入早停法时，"EarlyStopping 应该监控什么指标"这个问题引发了一系列关于分类评估指标的讨论。本文记录了从困惑到理解的完整思考过程。

---

## 1. 困惑的起点：为什么 Test Accuracy 和 val_auc_roc 对不上？

引入早停法后，最初选择监控 `val_auc_roc`（验证集 ROC AUC），mode='max'。但跑完后发现 Test Accuracy 不高，甚至和 AUC 的变化趋势关联不大。

**原因：AUC 和 Accuracy 测的根本不是一回事。**

- **Accuracy**：在**固定阈值 0.5** 上数对错。`P(好评) >= 0.5` 判为好评，再看判对了多少。
  它只关心"概率落在 0.5 的哪一边"。
- **AUC**：衡量**排序质量**。随机抽一正一负，模型给正样本打分更高的概率。
  它**完全不关心阈值，也不关心概率绝对值**，只关心相对高低。

**后果就是**：模型可以把所有正样本都排在负样本前面（AUC 接近 1），但如果它输出的概率整体偏低（比如正样本都给 0.45、负样本给 0.40），那么按 0.5 卡，全部判成负类，**Accuracy 反而很差**。排序对了 ≠ 卡在 0.5 上判得对。

**结论**：盯着 `val_auc_roc` 优化，Test Accuracy 跟着抖、关联弱，是完全正常的。推荐系统是排序问题，不是分类预测问题——AUC 只看排序、不看绝对概率值，天然对齐"把好东西排前面"这个目标。

---

## 2. 前置知识：混淆矩阵

所有分类评估指标都建立在混淆矩阵之上。假设阈值固定为 0.5：

|                  | 实际是好评（正样本） | 实际是差评（负样本） |
|------------------|:--------------------:|:--------------------:|
| **模型判好评**   | TP（真阳性）         | FP（假阳性，误报）   |
| **模型判差评**   | FN（假阴性，漏报）   | TN（真阴性）         |

从这四个值可以派生出所有常用指标：

| 指标 | 公式 | 含义 |
|------|------|------|
| Accuracy | (TP + TN) / 总数 | 判对了多少 |
| Precision（精确率）| TP / (TP + FP) | 判为好评的里面，有多少真是好评 |
| Recall（召回率）| TP / (TP + FN) | 所有好评里，捞出了多少 |
| TPR（True Positive Rate）| 同 Recall | 同上 |
| FPR（False Positive Rate）| FP / (FP + TN) | 所有差评里，多少被误判成好评 |

## 3. ROC 曲线与 ROC AUC

### 3.1 ROC 曲线的绘制

ROC（Receiver Operating Characteristic）曲线的核心思想：**把阈值从 1 慢慢调到 0，每个阈值都算一对 (FPR, TPR)，连成线。**

- 阈值很高（如 0.99）→ 几乎没人被判好评 → TPR ≈ 0，FPR ≈ 0 → 曲线起点 (0, 0)
- 阈值很低（如 0.01）→ 几乎所有人都被判好评 → TPR ≈ 1，FPR ≈ 1 → 曲线终点 (1, 1)
- **理想情况**：阈值一降，TPR 涨得很快，FPR 涨得很慢 → 曲线往左上角拱

```
TPR (召回率)
1 ┤  ..........
  │       ..   ← 好模型：往上拱，远离对角线
  │     ..
  │   ..
  │ ..
0 ┤............← 完全随机（对角线）
  └────────────────
  0              1
               FPR (假正例率)
```

### 3.2 AUC 的含义

**AUC（Area Under Curve）= ROC 曲线下面的面积**，取值 0 ~ 1：

| AUC 值 | 含义 |
|--------|------|
| 1.0 | 完美，存在某个阈值能把正负完全分开 |
| 0.9+ | 非常好 |
| 0.7 ~ 0.9 | 一般，可用 |
| 0.5 | 和瞎猜一样（对角线面积 = 0.5） |
| < 0.5 | 比瞎猜还差（把判断反过来反而好了） |

**一句话总结：ROC AUC 衡量的是"模型把正样本排在负样本前面的概率"。它跟阈值无关，只看排序。**

所以推荐系统爱用它——你根本不在乎 P 是 0.4 还是 0.6，你只在乎"好看的电影排在前面"。

## 4. PR 曲线与 PR AUC

### 4.1 PR 曲线的绘制

PR（Precision-Recall）曲线和 ROC 类似，也是遍历所有阈值，但画的是另一对指标：

- **Recall（召回率）**：好评里捞出了多少（和 ROC 的纵轴是同一个东西）
- **Precision（精确率）**：被判好评的里面，有多少是真的好评

阈值变化时：

- 阈值很高 → 只挑最有把握的判好评 → Precision 很高，Recall 很低
- 阈值放低 → 更多被判好评 → Recall 涨了，但混进来的假的也多 → Precision 下降

```
Precision (精确率)
1 ┤..
  │  .
  │   ..   ← 好模型：Precision 保持高
  │     ...
  │        ....
0 ┤...............
  └────────────────
  0              1
             Recall (召回率)
```

### 4.2 PR AUC 的含义

**PR AUC = PR 曲线下面的面积**，取值 0 ~ 1。它回答的问题是："在所有阈值下，精确率和召回率的综合表现如何。"

## 5. ROC AUC vs PR AUC：什么时候用哪个

|                    | ROC AUC                                | PR AUC                                 |
|--------------------|----------------------------------------|----------------------------------------|
| 分母是什么         | FPR 分母是**全部负样本**               | Precision 分母是**被判正的样本**       |
| 类别均衡时         | ✅ ROC 和 PR 都好用                    | ✅ ROC 和 PR 都好用                    |
| **正样本很少时**   | ⚠️ ROC 会**过于乐观**——分母大，FPR 涨不上去 | ✅ PR 会**暴露真相**——Precision 直接掉 |
| 推荐系统常用度     | ⭐ 更常用                              | 次之                                   |

**一句话选型：均衡用 ROC，正样本稀少用 PR。**

本项目的标签分布（train 集 46% 正 / 54% 负）基本均衡，用 ROC AUC 没问题。

## 6. 早停法监控指标的选择

### 6.1 困惑

引入早停法（EarlyStopping）时，要决定 `monitor` 参数监控哪个指标。这个选择决定了两件事：

1. **何时停**：被监控指标在验证集上连续 `patience` 轮不再变好，就停。
2. **回滚到哪一轮**（`restore_best_weights=True`）：回滚到被监控指标最优的那一轮。

### 6.2 四个候选指标对比

| 指标 | 特点 | 适合场景 |
|------|------|----------|
| **val_loss**（交叉熵）| 最灵敏的过拟合探测器：即使排序没变，只要模型对错误样本"越来越自信"，loss 就先涨。曲线平滑、转折早。 | 想最早、最稳地抓住过拟合 |
| **val_auc_roc** | 衡量排序质量，与阈值无关。推荐系统本质是排序，所以它最贴合业务目标。类别均衡时 ROC 不会误导。 | 想让"停/选"对齐推荐排序目标 |
| **val_auc_pr** | 只看正类的精确率/召回率，正样本稀少时才比 ROC 更有信息量。 | 正样本极度稀少的场景 |
| **val_accuracy** | 依赖 0.5 阈值、跳变不平滑、信息量低。 | ⚠️ 基本不推荐用于早停 |

### 6.3 最终选择

**对于推荐系统 + 类别均衡的数据，监控 `val_auc_roc`（mode='max'）是最合适的选择。**

理由：
- 推荐系统是排序问题，AUC 直接衡量排序质量，和业务目标一致。
- 标签 46/54 均衡，ROC AUC 不会像在极端不平衡数据上那样过于乐观。
- AUC 比 loss 抖一点，所以 `patience` 设为 3（不要太小）。

如果更看重"训练别过拟合"本身、想要最平滑的早停信号，可以换成 `val_loss`（mode='min'）。两种都是合理选择，区别在于优化目标不同。

```python
# 最终的早停配置
early_stopping = tf.keras.callbacks.EarlyStopping(
    monitor='val_auc_roc',   # 监控验证集 ROC AUC
    mode='max',              # AUC 越大越好
    patience=3,              # 连续 3 轮不提升就停
    restore_best_weights=True)  # 回滚到最佳那一轮的权重
```

## 7. 关于 Accuracy 的进一步思考

虽然推荐系统的核心目标是排序（所以用 AUC），但如果某天确实想让 Accuracy 数字好看，有两个层面的做法：

### 7.1 换早停监控指标

把 `monitor` 换成 `val_accuracy`（mode='max'），"你优化的"和"你最后看的"就一致了。在类别均衡时，0.5 阈值大致合理，val_accuracy 做早停指标是可行的（只是不如 AUC/Loss 稳定）。

### 7.2 不要死守 0.5 阈值

Accuracy 低很多时候不是模型差，是 0.5 这个阈值不是最优阈值。正确做法：**在验证集上扫一遍阈值，挑让验证集 Accuracy 最高的那个阈值，再用它去算测试集 Accuracy。**

这一步往往比换早停指标更能直接拉高 Accuracy——和人脸识别中"不同场景用不同识别阈值"是一个道理。

---

## 总结

| 概念 | 一句话 |
|------|--------|
| Accuracy | 固定阈值 0.5 下判对了多少，依赖阈值，不看排序 |
| ROC 曲线 | 遍历所有阈值，画 TPR vs FPR，看排序质量 |
| ROC AUC | ROC 曲线下面积，衡量"正样本排在负样本前面的概率"，与阈值无关 |
| PR 曲线 | 遍历所有阈值，画 Precision vs Recall，侧重精确率 |
| PR AUC | PR 曲线下面积，正样本稀少时比 ROC 更有信息量 |
| 早停监控 | 推荐系统 + 均衡数据 → `val_auc_roc`；想要最稳过拟合刹车 → `val_loss` |
| Accuracy 提升 | 换监控指标治标；在验证集上选最优阈值治本 |
